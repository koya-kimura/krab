# KRAB 技術HTMLのデザイン指示

`Assets/Krab/Docs/Html/` に、機能ごとに独立したHTML資料を置く。`midi.html` が現行の実例、`retro-brutal.css` が共通スタイル。新しい資料は同じCSSを相対パスで読み込み、内容に合わせて構成する。

## デザインの方向

添付のBRUTAL.IO風スクリーンショットを出発点とする、レトロブルータリズム。オフホワイトの地に原色の面、太い黒線、ぼかしのない右下へずれた影を使う。装飾は少なく、文字と構造が主役。技術資料なので、画面いっぱいの巨大な見出しは冒頭だけに抑え、以後は表・図・コードを読みやすい密度で配置する。

| 項目 | 指定 |
| --- | --- |
| 背景 | オフホワイト `#fbf8e8` |
| 文字・枠 | ほぼ黒 `#111`。主要カード・図表は `3px solid #111` |
| アクセント | 赤 `#ff5659`、黄 `#ffe600`、青 `#6ab7ef`、ミント `#72ecc1`、ピンク `#f38db2` |
| 影 | `8px 8px 0 #111`。ぼかし・半透明の影は使わない |
| 文字 | 本文は日本語を読みやすいゴシック、コード・ラベル・ナビは等幅。見出しは太字 |
| 幅と余白 | 最大幅は約1320px。各セクションを明確に区切る。狭い画面では1列にする |

## 共通部品の使い方

- `<head>` に `<link rel="stylesheet" href="retro-brutal.css">` を置く。外部フォント、CDN、画像ライブラリには依存させない。
- `.page` → `.topbar` → `main` → `.hero` → `section` → `footer` の順にする。`nav` は存在するセクションIDへのリンクだけを置く。
- `.hero` はページの内容を一文で説明する。技術資料では大見出しを1～2行に収める。
- `.section-head` と `.step` で章を示す。2章以降は見出しを大きくしすぎない。
- 概念の比較は `.card-grid` や `.interface-grid`、正確なシグネチャ・値・条件は `.table-wrap` 内の表を使う。
- データの流れは `.flow` / `.feedback`、階層は `.code-block` のテキスト図を使う。図の直後に文章でも関係を説明する。
- コード例は `<pre class="code-block"><code>…</code></pre>`。HTML特殊文字の `<` と `&` はエスケープする。
- 色は章や種類の区別に使う。色だけに意味を任せず、見出し・ラベルも付ける。
- 実装ファイルへのリンクはHTMLからの相対パスを使い、開けることを確認する。

## 技術資料の内容ルール

見た目よりも現在のコードの正確さを優先する。各機能の資料には、対象の責務、インターフェースと提供者／利用者、呼び出し経路、データ型と保存形式、所有者と寿命、失敗・境界条件、Sceneでの接続を載せる。公開契約と具象実装だけの挙動を混同しない。未実装の構想は現在の仕様として書かない。

表はスマートフォンで横スクロール可能にする。セマンティックな見出し、`aria-label`、キーボードのフォーカス表示を維持する。動きは必須ではない。`prefers-reduced-motion` を尊重する。

## 次回AIへ渡すプロンプト

> `Assets/Krab/Docs/Html/` に `<機能名>.html` を作成または更新してください。現行コードを読んで、クラスの責務、インターフェースのシグネチャと提供者／利用者、データフロー、保存形式、生成・破棄、境界条件、Scene構成を根拠付きでまとめてください。既存の `retro-brutal.css` を読み込み、`midi.html` の構成を参考にしてください。オフホワイトの背景、原色の面、3pxの黒枠、8pxずれた無ぼかしの黒い影を使います。大きな見出しは冒頭だけに抑え、本文は表・図・コードを優先して読みやすくしてください。外部CDNは使わず、実装ファイルへの相対リンクとモバイル表示を確認してください。現在の実装と将来案を明確に区別してください。

新しい部品が必要ならまず `retro-brutal.css` に再利用可能なクラスを追加し、機能固有のCSSを増やしすぎない。
