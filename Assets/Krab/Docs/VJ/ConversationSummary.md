# VJの関心・制作方法・道具づくり：対話のまとめ

2026-11-22。対話で整理した考え、参照、実装のつながりを記録する。思想の詳細は [制作姿勢](ArtisticIntent.md)、個別の先行事例は [リファレンス台帳](References.md) を参照。本人の確認済みの考えと、未確定の解釈を分けて読む。

## 何をしたいのか

好きな2Dグラフィックと、その動きを作り、それをその場の音楽に合わせて演奏したい。色、絵、動きを全体としてフィールで合わせ、音楽隊と一緒に演奏している感覚、デザインとしての魅力、観客の楽しさが重なる場を目指している。

楽しいのは、その組み合わせがうまくはまって盛り上がる瞬間である。音と映像がぴったり一致する気持ちよさだけでも満足でき、映像に独立した対旋律を必ず付け足すことは求めていない。

## 絵と動きの好み

2Dの造形の好みはPinterest等の視覚資料で示せる。好みを文章だけで定義し尽くすことが今回の主題ではない。

好きな静止グラフィックの造形や、モーショングラフィックの質を、リアルタイムに演奏できる映像へつなげたい。イージング、ADSR、位相差などによる有機的な動きに興味があるが、硬い動きや無機的な反復も重要である。

一部の3DのVJには、情報量が多く読み取れない、繰り返し見続けづらいという感覚がある。本人は技術への憧れや実現できないことへの感情もあり得ると留保している。これは3D全体の優劣の主張にはしない。

図形だけの表現の限界も認識している。画像、文字、背景を加えることで、見覚え、情報量、デザインの豊かさを作りたい。画像の親しみが観客の入り口になるという整理は、今後具体例で確かめる仮説として残す。

## コードで作る意味

コードによる制作は、パラメータを通して造形と動きの抽象化に取り組む方法である。

「この動きがいい」と感じたとき、何が変わるのか、どう変わるのか、複数の要素がどう関係するのかを取り出す。位置・大きさ・色、緩急・持続・減衰、同期・ずれ・反転などを、別の対象にも適用できる構造にする。

特定の曲と完成映像なら、一場面を感覚的に作り込める。未知の曲に応じて使う仕組みでは、その「いい感じ」が成立する条件をある程度取り出す必要がある。対話で確認した「MVなどと違って、なんとなくが難しい」という問題意識はこの意味である。

最終的な美的判断まで数値で説明することは目指さない。感覚的に作り、選び、演奏できるようにするための抽象化である。

## 準備と本番の分担

| 準備で作り込む | 本番で判断する |
|---|---|
| 造形、色や組み合わせの候補 | 今の曲に何を使うか |
| 一回の動きの輪郭と質感 | いつ叩くか、反復するか、休むか |
| プリセットと操作への割り当て | 重なり、画面の密度、切り替え |

一回の振る舞いは楽器の音色のように、ある程度決め打ちでよい。発火後に変形し続けることは必須ではなく、叩くタイミングと組み合わせを変えられれば演奏として十分である。

ジェネの価値は、ランダムで毎回違う映像が出ることだけではない。用意した表現で、まだ決まっていない時間の構成をその場で作れることにある。短いプリレンダを叩く演奏とも共通点があり、生成方法だけで演奏の価値を決めない。

ルーパーは自分で叩いた演奏を保持し、手を空け、ShapeSynthなどの表現を支えるもの。Session Viewやシーケンスへの関心はあるが、今回その仕組みを大きく作ることには進んでいない。

## VJとビジュアルミュージック

VJでは、未知の音楽を聴いて映像を判断するため、音の後手に回る立場を受け入れる。具体的な内容の映像が曲の文脈とずれることが気になり、抽象化した2Dの形・動きから合わせ方を探っている。

BPMを共有すればグルーブを作れる足場があり、その上はフィールで合わせられる、という実感がある。BPM一致だけでグルーブが必ず成立するという一般法則を主張しているわけではない。

一方、ビジュアルミュージックには「映像も音に負けたくない」という関心がある。DAWで音と映像をともにタイムラインへ置き、映像にも出力がある、というイメージである。ライブでの応答と、映像自体の時間構成は、別の実践として両立する。

「音を再現するAV／音と共存するAV」は未確定の問いとして残す。音を参考に作った動きを別のタイミングで叩くこともできるため、制作時の着想と演奏中の関係は分けて考える。

## 身体性と集団性

演者が楽しいことに加え、観客からどう見えるかを大切にしたい。制作方式を知る人だけに閉じず、音楽と映像の体験として楽しんでもらいたい。

[Pop Live Coding Encounters: Reflections on Practice](https://iil.is/pdf/2024_iclc_davis_et_al_pop.pdf) は、その関心の中心的な参照として本人が挙げた。制作過程、観客への伝わり方、コードに関心のない人とも楽しむことを考える入口になった。論文の立場をそのまま自分の全ての価値判断に適用するわけではない。

「クオリティや確実性を求められる現場ではポン出しが必要」という現場認識と、現在のオーディオビジュアル／趣味・同人的な場でリアルタイムに叩く実践がある。これは本人の認識として扱う。調査で見つかった固定素材とリアルタイム処理の併用例も見ながら、業務全体を一括りにしない。

## リファレンス探索で得た入口

[リファレンス台帳](References.md) に21件を整理した。作品、道具、研究を混同せず、近い点・違い・確認状態を付けている。現代VJの普及状況を網羅した調査ではなく、動画全編の鑑賞も未完了である。

特に対話が進んだのはVideosyncとSquares。Ableton LiveにVideosyncを追加し、映像をMIDIノート、Session View、Arrangement Viewで扱う仕組みである。Squaresは白い四角形をノートで発火し、サイズと不透明度にエンベロープを持つ。Ableton単体の標準機能ではなく、映像楽器にはMax for Liveも必要になる。[公式概要](https://www.showsync.com/videosync)・[Squaresの仕様](https://support.showsync.com/videosync/device-reference/instruments#squares)

これは「映像もDAWで演奏・構成する」という関心の具体的な先例になった。ShapeSynthと比較する際は、機能数より「何を映像の一音と捉え、どのパラメータを抽象化するか」を見る。

[draw(tokyo); #3の後記](https://note.com/monoton_music/n/n9275b3cb8870) は、Flowでの出演という本人にとって既知の接点があり、改めてVJを見て感想を考える対象になった。参照先の誰の出演を指すか等の詳細は、この対話では確定していない。

## この対話から行った実装

### 演奏用プリセット30個

参照元は、以前p5.jsで作った図形シンセ（未公開）。そのまま30ファイルを移植する方法ではなく、表現の着想を借り、ShapeSynthのValue共有を活かす構成にした。

- `01_Hit`、`02_Line`、`03_Array`、`04_Radial`、`05_Organic` の5タブに各6個。
- 既存の `group/name` でタブを分ける。新しいカテゴリ機能は追加していない。
- 同じValueを複数のサイズ・位置・回転・Opacity等へBind。振幅や符号はBase／Depth／Flip、時間差はDelayで扱う。
- 波形・周期・位相が異なる場合だけ別Valueを用意する。ValueはDocument単位の所有であり、プリセット間を動的に共有するライブラリではない。
- Circle、Rectangle、標準三角形とGroupの組み合わせ。頂点編集の新機能は追加していない。
- 2026-11-25にVisualを作り直すため削除した。Valueは共通ライブラリとして残している。

[追加計画](../../Modules/ShapeSynth/Docs/PresetCollectionPlan.md)と原本READMEに詳細・検証を残した。

### 赤い読込警告

旧Schemaの5件に由来する警告があった。後の確認では旧ファイルは保存先になく、正常な30個だけが残っていたため、削除自体を新たに実行したわけではない。

Preset Editorの一覧が古いままになる問題を修正し、保存先の変更を約1秒ごとに確認して一覧と警告を更新するようにした。編集中Documentは置き換えない。一時ファイルを追加・削除し、警告の出現／解消と編集状態の保持を実行確認した。

思想資料・30プリセット・一覧更新修正はコミット `b67f1cd`。

### グリッド比較画面 Gallery

Preset Editorの既存Sceneから開ける、保存済みプリセットの同時プレビューを追加した。

- Settings → ShapeSynth → Authoring → **Preset Editor - Gallery**。
- 6列のグリッド。現在の30個は5行で、各プリセットの動きを同時に確認する。
- Play／Loop、Restart、BPM、Beat指定、Seedを操作できる。
- Visual／Valuesの未保存編集を保持し、保存済みデータを比較する。保存先の追加・変更・削除にも追従する。
- 閉じるとプレビュー用カメラ・RenderTextureとイベント購読を解放する。

使い方と確認結果は [Preset Editor Workspace](../../Modules/ShapeSynth/Docs/PresetEditorWorkspace.md)。Unityコンパイル、全30セルの描画、停止／再生、開閉の解放、31個目の追加／削除、未保存Document保持を確認した。数値Coreの変更はない。

## 追加：ルーパーの実装

このまとめの後、本人の依頼により、p5版の操作を参考に8スロットのルーパーを実装した。録音・再生はShapeSynthに依存しないCommonのCore、プリセットIDとUI／MIDIの接続はShapeSynth側に置く。Record → Play → Clear、手動Triggerのみ録音、p5版と同じ秒数固定でクオンタイズなし。詳細と検証Sceneは [ルーパー](../../Modules/ShapeSynth/Docs/Looper.md)。

- 実際にVJ映像を見て、近い／違うと感じた時間帯と理由をリファレンス台帳へ残す。
- Pinterestの造形の好みと、公演で長く見られる映像の関係を比べる。
- 30プリセットを音楽に合わせて演奏し、動き・密度・重なりを調整する。
- Galleryの縮小表示と、本出力での細い線や動きの見え方を比べる。
- 実装したルーパーを演奏して操作感を確かめる。タイムラインや録音保存は、実際に必要になった範囲から別途設計する。
